# 统计聚合与 WAL 运维

统计保持 SQLite、单进程、单写连接及一个只读统计连接，不引入后台服务或 TTL 缓存。

## 数据一致性

`request_usage_hour` 按 UTC 小时、模型、渠道、密钥、应用和原始币种累计请求、错误、tokens、费用及延迟；`request_latency_day` 保存成功请求的每日精确延迟直方图和生成速度分子/分母。原始日志上的 INSERT/UPDATE/DELETE 触发器在同一事务中增减聚合，回滚、日志清理和更新同步生效，不存在异步缓存失效窗口。

初始化通过一个事务回填历史日志并安装触发器，版本记录使其可重复启动。大数据库首次启动会增加耗时和磁盘写入，应先备份、预留磁盘空间。当前百万日志单次回填约4.18秒，不能视为所有硬件的上限。不要手工删除聚合表或触发器；备份应包含完整 SQLite 数据库，并按原有一致性备份流程操作。

新日志保存计费时币种；历史空币种依然按现行模型价格回退，无法补回过去被修改的币种。聚合保留模型和空币种，因此修改当前价格、名称或删除渠道/密钥不会使缓存中的展示元数据过期。金额沿用原有 REAL/六位小数语义，没有引入币种自动兑换或新精度承诺。

每次仪表盘或趋势响应读取同一个只读事务快照，使用固定 UTC 时间边界；不同 HTTP 响应之间可以包含新到日志。查询继承请求取消，且最多10秒（含等待连接），避免被放弃的查询长期固定 WAL 检查点。最近60秒 RPM/TPM 仍从带时间索引的原始日志读取。延迟直方图保持精确最近秩分位数，并非近似采样。

## WAL 文件

写连接设置 `wal_autocheckpoint=1000` 和 `journal_size_limit=16777216`。SQLite 通常复用已检查点的 WAL 文件；后者限制 WAL 重置后保留的文件大小，**不是活动读事务或大写事务期间的硬上限**。不在请求路径强制阻塞式 TRUNCATE。详见 [SQLite 官方说明](https://sqlite.org/pragma.html#pragma_journal_size_limit)。

监测 DB/WAL/SHM 总量、长查询和磁盘余量。基准记录的 PASSIVE 检查点是在负载结束后诊断，没有强制截断文件。一次性百万日志装载可在开始测量前产生约105 MiB WAL；最新负载测试结束回落至16 MiB，并不意味着峰值从未超过16 MiB。

## 成本和边界

聚合将读取成本转移到日志写入及额外存储。单维度百万日志装载从2.76秒升至6.50秒；高维度样本的百万日志产生12万聚合行、装载14.24秒，仪表盘约1.05秒、趋势0.265秒。极高基数应用名、模型名或延迟值会减少压缩收益，不能据低基数结果承诺任意容量。查询超时返回错误，不返回伪造的零统计。

复现命令和原始测量见 [验证记录](VALIDATION.md)。仍需独立硬件、多次重复、多面板、数小时负载及固定数据量内存稳定性验证。
